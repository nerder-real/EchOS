# EchOS v1.3.2 发布清单

> 基线：`f6da9e4`（v1.3.1 已发布）。本清单对应当前工作树，发布正文见同目录 `v1.3.2.md`。

## 一、当前状态

- 工作树有 20 个已跟踪文件修改，另有未跟踪 `core/tun_breaker.go`、两份 `docs/releases/v1.3.2*.md`。
- 本轮新增（均在 `gui/Sources`）：窗口三态尺寸对齐（`App.swift` / `ContentView.swift`）、规则入口统一到标题后（`ContentView.swift`）、空规则双重拦截（`AppState.swift` 的 `addRule` + `persist`）。
- `gui/Info.plist` 仍是 `1.3.1`；CI 会按 tag 自动写回 `1.3.2`，本地出包前需手工确认。
- 生产授权服务当前版本 `v26.11.23-0321`，本次客户端发版不需要重新部署服务端。
- `license-server/` 已列入根 `.gitignore`，不得入库、不得上传。

## 二、必须先确认的差异

- 旧版 `v1.3.2.md` 草稿写过「更新失败保留已装版本」和「备份/分享文件仅当前用户可读」。
- 当前工作树没有这两处实现：更新脚本仍是先删旧 App 再拷贝，本地备份仍是 `.atomic` 写入且未设 0600。
- 发布正文已按实际代码重写。若要恢复这两条卖点，需先补实现并验证，不能只改文案。

## 三、发版前检查

- 确认 `ECH_LICENSE_URL` 只从环境变量或 `~/.echos-build-license` 读取，权限 600，仓库内无明文。
- 确认 `ECH_UPDATE_REPO` 由 git remote 或 CI `${{ github.repository }}` 注入。
- 确认 Worker 兼容日期为 `2025-09-15` 或更晚，README 口径已修正。
- 本地通用包执行 `./build-local.sh`，产物应为 `build/EchOS-mac-1.3.2-universal-x64.dmg`。
- 本地包如用于开发调试，须确认是否故意打出「不启用授权」包；正式发版只能走 CI 且必须注入授权地址。
- 检查 DMG 版本号、图标、拖入 Applications 布局与 Gatekeeper 提示。

## 四、必测矩阵

- 三态切换：未配置授权、待激活、已激活，窗口高度不跳动（实测启动全程 frame 固定 804，无 resize/位移）。
- 规则折叠/展开 × 日志折叠/展开六格矩阵，含搜索框分档。
- 规则入口：改规则后标题处出现「待生效·点此重启应用」，点它内核重启生效；删空全部规则后该入口仍在。
- 空规则：已有空行时再点「添加规则」应弹提示且不新增；填好目标后可继续加；重启 App 后配置不残留空行。
- 日志四档：关闭、仅错误、警告、全部，切换不丢记录，自检/授权历史可回看。
- 日志滚动：切类别、新行到达、超过 2000 行截断后仍跟随最新一条。
- TUN：内核失败信息出现在运行日志；运行中清空日志同步生效。
- SOCKS5：仅 no-auth、仅 username/password、双方法、未配置仅 0x02 四类握手。
- 更新：既有包可被新版本替换；失败路径不得作为本次发布结论。

## 五、发布步骤

- 按单主题拆分提交，标题按既往规范保持简短。
- 打标签 `v1.3.2` 并推送；CI 自动写回版本号、注入授权地址、构建 DMG 并读取 `docs/releases/v1.3.2.md` 作为正文。
- 推送沿用代理绕行参数：`git -c "http.https://github.com/.proxy=" push origin main --tags`。
- Release 生成后确认附件为 `build/EchOS-mac-1.3.2-universal-x64.dmg`，正文无授权地址明文。

## 六、发布后验证

- 从 Release 页下载 DMG，确认可打开、可拖入 Applications、首次运行授权流程正常。
- 自动更新路径确认 `.updated-version` 标记只在新包成功启动后写入。
- 授权后台确认平台筛选、`.xlsx` 导出与生产版本号正常。
- Worker `wrangler tail` 观察连接与断开日志，无异常放大。
- 保留上一版 DMG 与 tag，便于回滚。
